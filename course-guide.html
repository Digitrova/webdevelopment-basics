PART 01 / PEHLE —

Website ke Types

Sab se pehla kaam: yeh samajhna ke website kis tarah ki hai. Website ka type hi batata hai ke us mein backend chahiye ya nahi, kitna kaam hai, aur student ko kya seekhna parega. Student ko pehle yahan stop karein — bina type samjhe koi website banana ulta hai.

English summary

A website's type determines everything downstream: whether it needs a database, which stack to learn, how much time it takes and what it costs to host. The 12 types below are ordered by complexity, from a plain static page to a full multi-vendor platform. Pick the type first, then pick the tools — never the other way round.

Website types ka map — complexity ke hisaab se

Left se right complexity barhti hai. Student ko sab se left se shuru karna chahiye — har level pichle ka skill assume karta hai.

Static / Simple Level 1

Sirf files — koi database nahi. Browser mein hi chalti hai.

  • Portfolio website
  • Landing page (one-pager)
  • Blog (personal)
  • Info / brochure site

CMS Based Level 2

Content admin panel se edit hota hai. Code kam, content zyada.

  • WordPress business site
  • Documentation / help site
  • School / college portal
  • Membership site

Transactional Level 3

User action se data badalta hai — cart, booking, listings.

  • E-commerce store
  • Directory / listing site
  • Booking & reservation
  • Course / event platform

Platform Level 4

Login, dashboards, multi-user, roles. Sab se mehnat wali.

  • Web app / SaaS dashboard
  • Marketplace (multi-vendor)
  • Social / community app
  • Online ERP / CRM

PART 02 / PHIR —

Complete Setup (Environment)

Website banane se pehle computer ko tayyar karna. Yeh ek din ka kaam hai lekin agar sahi na ho to baqi sab ka kaam ruk jata hai. Is part ko student ke saath bilkul ek saath karein — har command khud terminal mein chalayein, sirf screenshot mat dikhayein.

English summary

Environment setup = installing the four tools every web developer needs (editor, browser, Git, Node), creating a clean project folder structure, and wiring up a local preview server. Do this once, correctly, and the student can build any type of website afterwards. Each command below is meant to be typed by the student, not read aloud.

Setup ki 8 steps

1

VS Code install karein

~5 minutes · manual

Browser mein code.visualstudio.com kholein, "Download for Windows" par click karein, aur installer chalayein. Install ke dauran "Add to PATH" wala checkbox zaroor tick karein — warna terminal mein command nahi chalega.

  • Mac users: "mac" button, Linux users: ".deb" ya tarball
  • VS Code khulne ke baad Windows key + Ctrl+Shift+P (Mac: Cmd+Shift+P) dabaayein — yeh "Command Palette" hai. Shell Command: Install 'code' command in PATH search karke chalayein. Is se terminal mein code . se project khul jayega.
2

4 extensions install karein

~8 minutes · VS Code ke andar

VS Code mein left side ke "Extensions" icon par click karein (ya Ctrl+Shift+X) aur neeche diye gaye chaar extensions search karke Install karein.

ExtensionKya karta hai
Live ServerCode save karte hi browser khul ke live page dikhata hai
HTML CSS SupportVS Code ko classes ka suggestion deta hai (typo pakadta hai)
PrettierCode ki marzi se thoda saaf likhta hai
ESLint (Week 6 ke baad)JavaScript ke ghaltiyan pakadta hai

Install ke baad VS Code ek baar dobara restart karein — tabhi sab extensions activate hote hain.

3

Git install karein aur check karein

~10 minutes · terminal

git-scm.com se download karke default settings ke saath install karein. Windows par install ke baad VS Code ko dobara kholna zaroori hai, warna Git detect nahi hota.

Phir terminal kholein: Windows par Win + R → cmd → Enter. Mac par Terminal app, Linux par Ctrl+Alt+T.

# Git sahi install hua ya nahi — yeh dono commands chalayein
git --version
# Expected output: git version 2.4x.x

# Apni identity set karein (ek baar, hamesha ke liye)
git config --global user.name "Your Name"
git config --global user.email "ali@example.com"

# GitHub se connect karne ke liye SSH key bhi banani hogi (aap baad mein batayenge)
4

Node.js (LTS) install karein

~5 minutes · React phase ke liye

nodejs.org kholein aur LTS wala button download karein (number ke saath LTS likha hota hai — wahi sahi hai). Install default hi rakhein.

node -v
npm -v
# Expected: v20.x.x  aur  10.x.x  (versions thori different ho sakti hain)

Dono commands ka jawab aa jaye — iska matlab Node install ho gaya hai.

5

Project folder banaayein

~5 minutes · folder structure

Terminal mein apne projects ke liye ek jagah banaayein. my-website naam rakhein:

# Desktop pe jaayein (ya koi bhi jagah)
cd Desktop
mkdir my-website
cd my-website

# VS Code mein yeh folder kholein
code .

Ab folder ke andar yeh structure banayein (mkdir command se ya VS Code mein right-click → New Folder):

my-website/
├── index.html          ← main page (sab se zaroori)
├── about.html          ← dusri pages
├── css/
│   ├── style.css       ← main styling
│   └── responsive.css  ← mobile wale styles
├── js/
│   └── main.js         ← JavaScript
├── images/             ← photos, logos, icons
├── fonts/              ← custom fonts (optional)
└── README.md           ← project ka tafseel
Zaroori usool: Folder ka naam aur file ka naam kabhi "final", "final2", "new folder" mat rakhein. index.html ka naam hamesha wahi rehna chahiye — hosting usi ko dhoondti hai.
6

Pehli file banaayein aur Live Server chalaayein

~5 minutes · pehla test

index.html mein yeh sab se pehle code likhein:

<!DOCTYPE html>
<html lang="ur">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Meri Pehli Website</title>
  <link rel="stylesheet" href="css/style.css">
</head>
<body>

  <h1>Hello Duniya! </h1>
  <p>Yeh meri pehli website hai.</p>

  <script src="js/main.js"></script>
</body>
</html>

Ab VS Code mein index.html par right-click → "Open with Live Server". Browser khul jayega aur har save par page refresh ho jayega. Yehi student ka asli kaam hai — ab woh bina kuch deploy kiye website bana sakta hai.

7

GitHub account + pehla commit

~15 minutes · backup + free hosting

github.com par account banayein (free). Phir terminal mein:

git init
git add .
git commit -m "Pehla commit: setup done"

# GitHub pe naya repository banayein (browser mein), phir:
git branch -M main
git remote add origin https://github.com/USERNAME/my-website.git
git push -u origin main
Faida: Ab har baar git add . → git commit -m "kya kiya" → git push likhne se purana kaam ka backup mil jata hai, aur GitHub Pages se website free live ho jati hai (Part 4 mein tareeqa).
8

Chrome DevTools seekh lein

~20 minutes · sab se qeemti skill

Browser mein F12 (ya Ctrl+Shift+I) dabaayein. Yeh student ka "x-ray" hai — website ke andar jo ho raha hai sab dikhta hai.

Elements tab

Left mein poora HTML + CSS dikhta hai. Kisi bhi element par click karein to uski CSS rules right mein highlight ho jati hain. Yeh CSS seekhne ka sab se tez tareeqa hai — guess karna band, sach pata chal jata hai.

Console tab

Yahan JS ke errors aate hain. Console mein console.log("test") likh ke save karein — message turant dikh jayega. Har website ka pehla kaam: console khol ke rakhna.

Aur teen tabs: Console (errors), Network (file load ho rahi hai ya nahi), Responsive (phone size preview — phone icon par click karke iPhone select karein).

Setup khatam hone ki checklist: VS Code khul raha hai ✔ · Live Server chalta hai ✔ · git --version jawab deta hai ✔ · node -v jawab deta hai ✔ · index.html browser mein khul raha hai ✔ · F12 par Elements tab khul raha hai ✔. — Student se kahein ke yeh 6 cheezein khud check kare, aap sirf dekh lein.
PART 03 / PHIR BHI —

Website banane ka Tareeqa (10 Steps)

Ab type decide ho gaya hai. Ab actual kaam. Yeh 10 steps har website ke liye same hain — portfolio ho ya e-commerce. Student ko yehi sequence yaad karwana hai: pehle sochna, phir banana, phir test, phir live karna.

English summary

Every website — regardless of type — is built with the same 10 steps: define the goal and page list, sketch the design, create the folder structure, write semantic HTML, style with CSS, make it responsive, add JavaScript behaviour, optimise images, test properly, then deploy with a domain. Skipping steps 1, 9 or 10 is the most common reason a student ends up with a website that looks good but does not work.

1

Goal aur pages ka faisla (Sitemap)

20 minutes · pehle coding se

Sab se pehle paper par likhein ke is website mein kaun kaun se pages honge aur har page par kya hoga. Sketch banana bhi isi step mein hai — paper par ya Figma mein.

Portfolio ka example sitemap:

Home      → Hero + mera introduction + 3 projects
About     → meri kahani, skills, timeline
Projects  → 6 project cards (filter button bhi)
Contact   → form + email + social links
  • Har page ka ek maqsad likhein — ek line. Agar do maqsad ho to woh do alag pages hain.
  • Abhi 5 se zyada pages mat banayein. Pehle 3 pages perfect banaayein, phir aur add karein.
2

Design / Wireframe

30–90 minutes · Figma ya paper

Layout ka naksh banayein. Pehle sirf boxes (sirf shapes, koi rang nahi) — isay kehte hain wireframe. Rang baad mein add honge.

  • Free aur beginner-friendly: pencil (paper.com) ya Figma ka free plan
  • Important: mobile layout bhi banaayein — desktop ki copy mat banayein
  • Ek color + font system tay karein: 1 primary color, 1 accent, 2 font sizes, 1 button style
3

Folder structure + HTML skeleton

20 minutes · setup wala hissa

Setup (Part 2, Step 5) wala folder structure banayein. Phir har page ke liye ek skeleton HTML likhein — abhi sirf structure, content baad mein aayega.

<header>   ← logo aur navigation
  <nav></nav>
</header>

<main>
  <section>  ← hero / intro
  <section>  ← main content
  <section>  ← gallery / features
  <section>  ← contact form
</main>

<footer>  ← copyright, links
</footer>
Wajah: <header>, <main>, <footer> sirf sirf decoration nahi — Google inhe padhta hai (SEO) aur screen-reader users inhe use karte hain (accessibility). Student ko yehi structure yaad karwaayein, har page par.
4

HTML likhein — semantic aur saaf

2–4 hours · content ke saath

Ab content daalein. Har element ka sahi tag chunein — yeh sab se important rule hai.

GalatSahiKyun
<div> har jagah<header> <nav> <main> <section> <article> <footer>SEO + accessibility
<b> heading ke liye<h1> … <h6>Heading ka hierarchy
<p> title ke liye<title> (head mein)Browser tab ka naam
Image bina alt<img src="..." alt="kya dikha raha hai">Blind users ke liye zaroori
 
<nav>
  <ul>
    <li><a href="#about">About</a></li>
    <li><a href="#projects">Projects</a></li>
    <li><a href="#contact">Contact</a></li>
  </ul>
</nav>

Pehle poora HTML likh lein, styling baad mein. Yeh beginner ka sab se badi ghalti hai — dono saath karna.

5

CSS — box model, Flexbox, Grid

4–8 hours · styling

CSS ko 3 hisson mein seekhein, isi tarteeb se. 1) Box model — har element ka margin (bahar), padding (andar), border aur content. 2) Flexbox — ek line mein cheezein side-by-side (nav, buttons, cards). 3) Grid — 2D layout (gallery, dashboard).

/* Flexbox: navigation bar */
.nav {
  display: flex;
  align-items: center;      /* cross-axis par center */
  justify-content: space-between; /* main axis par faila do */
  padding: 16px 32px;
}
.nav a {
  text-decoration: none;
  color: #3a4256;
  margin-left: 24px;
}

/* Grid: 3 column cards, gap ke saath */
.cards {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  gap: 24px;
}
Teacher ka tareeqa: Har styling rule ke saath likhwayein "yeh kya karta hai?" — jawab sirf English mein dein, jaise "flex container apne children ko ek line mein rakhta hai". Student ko ratta nahi, samajhna chahiye.
6

Responsive banaayein (mobile-first)

2–4 hours · zaroori step

Us din 70% log phone se website kholte hain. Is liye pehle mobile ka design banaayein, phir bade screen par layout khule. Isay kehte hain mobile-first.

/* Base: phone wala layout (bina kisi condition ke) */
.cards { grid-template-columns: 1fr; }
.nav-links { display: none; }

/* 768px se upar: tablet + laptop */
@media (min-width: 768px) {
  .cards { grid-template-columns: repeat(2, 1fr); }
  .nav-links { display: flex; }
}

/* 1024px se upar: desktop */
@media (min-width: 1024px) {
  .cards { grid-template-columns: repeat(3, 1fr); }
}
  • Breakpoints: 768px (tablet), 1024px (laptop), 1440px (bada screen)
  • Test: DevTools → phone icon → iPhone aur iPad — dono par check karein
  • Images par max-width: 100% zaroor lagayein, warna phone par scroll aayega
7

JavaScript — website ko "zinda" karein

3–6 hours · interactivity

HTML se structure banta hai, CSS se shakal, JavaScript se kaam. Pehle sirf 3 cheezein seekhein: element dhoondna, event sunna, aur content badalna.

// 1) Element dhoondna
const button = document.querySelector("#menu-btn");

// 2) Click ka event sunna
button.addEventListener("click", () => {
  // 3) Content / class badalna
  document.querySelector(".nav-links").classList.toggle("active");
});

CSS mein mobile menu ke liye sirf ek rule chahiye:

@media (max-width: 767px) {
  .nav-links.active { display: flex; flex-direction: column; }
}

Pehle 3 JS projects banayein: mobile menu toggle, dark/light mode toggle (localStorage ke saath), aur form validation.

8

Images aur assets optimise karein

45 minutes · speed ka masla

Websites slow isliye hoti hain ke images asli size mein hoti hain. Ek 4 MB ki photo page ko 3 second tak khaali dikhati hai.

  • Photos ko WebP format mein convert karein (free: tinypng.com, squoosh.app) — size 70–80% kam ho jati hai
  • Har image par loading="lazy" (sirf screen par aaye tab load ho)
  • Icons ke liye inline SVG behtar hai PNG se
  • Total page size 1–2 MB se kam rakhein
<img src="images/project.webp" alt="Bakery ka cake" loading="lazy" >
9

Test karein — 6 checks

1 hour · "kya sach mein kaam kar rahi hai?"

Student ka sab se aam ghalti: website ban gayi, lekin test kabhi nahi ki. Neeche ka checklist har website par lagayein.

Console khaali hai?

F12 → Console. Koi bhi red error nahi hona chahiye.

Mobile par dekha?

DevTools → phone icon → iPhone + iPad preview.

Sab links kaam kar rahe hain?

Har link par click karein — koi dead link na ho.

Form submit ho raha hai?

Actually bhej ke dekhein ke message aa raha hai.

Text padhne layak hai?

Chhota phone par bhi font chhota na lage, dark/light contrast theek ho.

Speed test

pagespeed.web.dev → URL daalein. Score 90+ hona chahiye.

10

Deploy karein — website live + domain

1–2 hours · free hosting

Yeh woh step hai jahan student ko "maine website bana li" ka ehsaas hota hai. GitHub Pages aur Netlify dono free hain — beginner ke liye Netlify drag-and-drop sab se aasan hai.

# Netlify ka tareeqa (10 second):
# 1) app.netlify.com → "Add new site" → "Deploy manually"
# 2) poora project folder drag & drop kar dein
# 3) 30 second mein live URL mil jayega
# 4) Site settings → Change site name → apna naam
#    (example: ali-portfolio → ali-portfolio.netlify.app)

GitHub Pages ka tareeqa (agar aap Git seekh rahe hain to yehi behtar hai):

# Settings → Pages → Source: main branch → / (root) → Save
# Phir link milega: https://USERNAME.github.io/my-website
Domain (custom name): Apna asli naam jodne ke liye domain khareedna hota hai (GoDaddy, Namecheap, Google Domains — saal mein kuch dollars). Usay Cloudflare ya Netlify se jorr dein — SSL (https) automatic mil jata hai. Student ko pehle free subdomain par website live karwaayein, domain baad mein.
PART 04 —

7 Din Mein Pehli Website (Practical Plan)

Student ko theory bohat zyada na dein. Uski pehli website ek hafte mein live honi chahiye — confidence isi se banti hai. Roz 2–3 ghante dein, 7 din, aur ek portfolio live ho jayegi.

English summary

Give the student one finished, live website in the first week — do not wait until they "know enough". This 7-day plan builds a personal portfolio from an empty folder to a deployed URL: plan, HTML, CSS, responsive, JavaScript, polish, deploy. Two to three focused hours per day is enough. Momentum matters more than completeness at this stage.

Roz kitna waqt

Total ≈ 16–17 ghante — hafte mein 7 din, roz 2 se 3 ghante. Is se zyada dein to 3 din mein bore ho jayega; kam dein to 2 hafte lag jayenge.

PART 05 —

12-Week Curriculum (Basics → React)

Ek bilkul beginner ke liye 12 hafte ka complete course. Har module ke end par ek deliverable hai — yaani kuch hai jo student ka apna hai. Topics sirf list nahi, har module ke saath output bhi hai.

English summary

A structured 12-week syllabus for a complete beginner, ending with React. Each module produces a tangible deliverable so progress is visible and the student always has something to show. Weeks 1–8 build the fundamentals (HTML, CSS, responsive, JavaScript, Git); weeks 9–12 introduce React, Tailwind and API work. One module per 1–2 weeks, roughly 3–4 focused hours per week.

PART 06 —

React Phase — Basics ke baad

Ab tak student ne plain HTML/CSS/JS seekh liya hai. React us ka natural next step hai — lekin sirf tab jab portfolio project complete ho. Is part mein poora React setup, component ka concept aur aapka pehla React app hai.

English summary

React is the natural next step after vanilla JavaScript — but only after the student has shipped a complete vanilla project. React's core idea is splitting the page into reusable components that own their own state. Setup is one command, the component model takes about two weeks to click, and the payoff appears the moment the student builds their first dashboard.

Vanilla JS mein

Ek badi HTML file. Sab kuch ek jagah. Naya section add karo to wahi file phat jaati hai. 500 line cross karte hi maintenance mushkil ho jata hai.

React mein

Page chhote components mein toot jaata hai. Har component apna data (state) rakhta hai. Button wala component 5 jagah use ho sakta hai — ek jagah change karo, sab jagah badla.

Component ka concept — ek nazar

ProjectList sirf data rakhta hai, Card sirf dikhata hai. Data badalna ho to sirf List badlein — Cards ko haath nahi lagana.

React setup — 3 commands

npm create vite@latest my-app -- --template react
cd my-app
npm install
npm run dev

Terminal mein npm run dev chalane par browser mein localhost:5173 khul jayega. Ab har file change par turant update ho jayega.

Pehla component — counter

// src/App.jsx
import { useState } from "react";

function Counter() {
  const [count, setCount] = useState(0);

  return (
    <div>
      <p>Count: {count}</p>
      <button onClick={() => setCount(count + 1)}>
        Badhaayein
      </button>
    </div>
  );
}

export default Counter;

Kab React use karein?

  • React use karo: jab page ke sections repeat hon, state zyada ho, ya app ban rahi ho (dashboard, cart, admin panel).
  • Plain HTML/CSS use karo: jab ek simple page ho — portfolio, landing page, brochure. React wahan extra kaam hai, fayda nahi.
  • Sirf Tailwind/JS: jab design-focused static site ho — speed aur simple rakhte hain.
Sab se aam ghalti: Student React isliye seekhta hai kyon ke "market mein React hai" — lekin pehle 2 projects plain HTML/CSS mein banana zaroori hai. Bina JS ke React seekhna = bina gram ke guitar. React ka kaam samajhne ke liye pehle JS aana chahiye.

Har project ke baad ka rule

  • Deploy karo — live URL kaam ka hissa hai
  • 2 minute samjhao — bina code dekhe, kisi ko batao ke yeh website kaise bani
  • Ek bug theek karo jo aapne khud pakda ho
  • README likho — kya hai, kaise chalana hai

Project choote waqt dhyan rakhein

  • Sirf woh project jo khud kaam kar raha ho — half-done project se behtar hai ek chhota complete project
  • Content apni zindagi se lo (apni bakery, apna university, apna sheher) — copy-paste templates se seekh nahi aata
  • Har project ke end par ek naya bug khud introduce karein aur theek karein — yehi asli practice hai
PART 08 —

Common Ghaltiyan (Inse Bachayein)

Yeh 10 ghaltiyan har beginner karta hai. Agar student inhein bach le to uski speed do guna ho jati hai. Har ghalti ke neeche "sahi tareeqa" likha hai — isay notebook mein note karwaayein.

English summary

These ten mistakes are the ones that slow beginners down the most — desktop-only design, unoptimised images, no Git, chaotic file naming, writing HTML and CSS at the same time, and never opening the console. Each entry below pairs the mistake with the correct practice, so it doubles as a self-review checklist for every project.

#GhaltiSahi tareeqa
1Sirf desktop par designMobile-first CSS — pehle phone ka layout, phir media queries se bada
2HTML aur CSS ek saath likhnaPehle poora HTML (content ke saath), phir poora CSS, phir JS
3Console kholna hi nahiHar page kholte hi F12 → Console. Red error = ruk jayein
4Original size ki imagesWebP format, loading="lazy", max-width:100%
5Git use na karnaHar kaam ke baad commit — 5 minute ka kaam, bug aaye to 1 click wapas
6File naming: final2.htmlNaam apne kaam ke mutabiq — about.html, style.css
7Folder structure adhooracss/, js/, images/ folders pehle se — baad mein sort karna mushkil
8Samajhe bina copy-pasteHar code block ko type karne ke baad 2 minute mein explain karein
9Alt text aur labels chhorr denaHar image par alt, har input par <label> — yehi accessibility hai
10Deploy karna hi nahiHar project ke end par deploy — doosrona tayyar karta hai, shayad nahi
Teacher ka tareeqa: Har hafte ka review session 20 minute ka rakhein. Student ko sirf yehi table dikhayein aur kahein "in 10 mein se kaun se 3 aapne kiye?" — is se khud ka review seekh jata hai aur aapko har baar lecture nahi deni parti.

Command Cheat Sheet

Ek saaf copy-paste sheet — isay print karein aur student ke desk par rakhein. In commands ke baghair project ka koi kaam nahi chalta.

Git — roz ka kaam

git status              # kya badla hai?
git add .               # sab stage karo
git commit -m "msg"     # save point banao
git push                # GitHub par bhejo
git log --oneline       # purana kaam dekho

git branch feature-x    # naya branch
git switch feature-x    # branch par jao
git switch main         # wapas aao
git merge feature-x     # jorr do

git checkout .          # sab changes wapas (danger!)

Node / npm — React phase

node -v                # Node installed hai?
npm -v                 # npm version

npm create vite@latest my-app -- --template react
cd my-app
npm install
npm run dev             # localhost:5173
npm run build           # production build
npm run preview         # build preview

Folder mein jaldi jana

cd my-website      # folder mein jao
ls                # files dekho
mkdir images       # naya folder
code .             # VS Code mein kholo
Ek hikayat: Terminal mein rm, del ya rm -rf kabhi mat chalayein jab tak poori tarah samajh na aaye — ek galti se poora project folder khatam ho sakta hai. Aur kabhi bhi git commit se pehle git status zaroor dekh lein.
